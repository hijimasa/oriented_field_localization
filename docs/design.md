# 設計

[English](en/design.md) | 日本語

## 目的と非目的

2D `LaserScan` と占有格子地図から、**初期位置を仮定せずに**地図座標の
`(x, y, yaw)` を 1 スキャンで推定し、収束後は事前姿勢の周りを局所探索で追い続ける。

次は範囲外である。

- ICP / スキャンマッチングによる姿勢の微修正 (本手法の格子分解能で足りない用途)
- 複数スキャンの累積、SLAM、地図生成
- 内部オドメトリ (scan-to-scan)。`/odom` が無い場合は最後の採択姿勢を事前姿勢に使う

## スコア

テンプレート (スキャン) と地図をそれぞれ次の 3 チャネルの場に変換する。

```text
f(p) = ( mass(p), lam * mass(p) * nx(p), lam * mass(p) * ny(p) )   画像座標 (y 下向き)
```

- `mass` は壁画素の有無 (0 / 1)。地図側は占有格子を 3x3 dilate した二値、
  スキャン側はビーム端点を同じ格子へ落として 3x3 dilate したもの
- `(nx, ny)` は**観測側を向く単位法線**。地図側は自由空間マスクの勾配 (自由側向き)、
  スキャン側は隣接ビームの接線に垂直な向きをセンサ側へ揃えたもの。両側が自由な薄壁
  では地図側の勾配が立たず、そこは法線なし = 質量チャネルだけに退化する

姿勢 `(p, alpha)` のスコアは

```text
s(p, alpha) = < f_map , R_alpha f_scan >_p / sqrt(E_scan)
```

で、`R_alpha` は位置も値も回す回転、`E_scan` はテンプレート側のエネルギー総和である。

**分母をテンプレート側だけにしてあるのが要点である。**候補位置ごとの地図側エネルギー
でも割る (コサイン正規化する) と、候補ごとに参照信号を作り直すのと同じことになり、
候補間の比較可能性が壊れて順位付けが落ちる。実測では top-1 が 85.2% から 73.1% まで
下がった (`radon_global_localization/docs/image_space_control.md` 5.)。

## 探索

画像ピラミッドの粗密探索。

```text
粗段 (既定 0.2 m/px)
  alpha を coarse_angle_step 刻みで全周
    テンプレート canvas を alpha 回転 -> 順 DFT
    地図側スペクトル (起動時に前計算) と周波数域で掛けて 1 回の逆 DFT
    -> 全位置のスコア場が一度に出る
    角度ごとに peaks_per_angle 個のピークを NMS 付きで保持
  候補を NMS して candidate_pool_size へ刈る
細段 (0.1 -> 0.05 m/px)
  候補ごとに ±refine_angle_window 度 x ±refine_search_m を疎な点列の直接相関で精密化
  NMS で刈る (中間段は intermediate_pool_size、最終段は candidate_pool_size)
```

**位置について全点のスコア場が一度に出るのがこの定式化の利点である。**同じ表現を
サイノグラム空間で照合すると、位置は 180 行を横切る正弦波経路になって FFT に落ちず、
粗い格子で標本化するしかない。その差が成績に出る (benchmark.md)。

### 相関用の外挿は最小で足りる

センサ位置はパディング前の地図の内側にしか置かないので、テンプレートが触る画素は
`[margin - R, margin + map_w - 1 + R]` (R = footprint 半径 = `max_range / 段の解像度`)
に収まる。地図は既に `margin` だけゼロ詰めしてあるので、**追加で要るのは
`max(0, R - margin)` だけ**である。`margin_pixels >= ceil(sqrt(2) * max_range /
match_resolution) + 1` を満たせば外挿は 0 になり、DFT が最小になる。

素朴に `R` だけ広げると DFT の一辺が 1.4 倍になり、粗段のコストが 2 倍になる。

## TRACK (局所探索)

収束後は地図全域を探す必要がない。`track()` は事前姿勢の周り
(`±track_search_m`、`±track_angle_window_deg`) だけを走査する。

粗段は FFT ではなく**疎な点列の直接相関**で走る。位置の候補数が地図全体の数百分の一に
なるので、FFT のオーバーヘッドを払うより直接評価するほうが安い。細段 (refine) は
GLOBAL と完全に共通で、スコアの定義も同じなので、GLOBAL の候補と TRACK の候補は
そのまま比較できる。

**TRACK の計算量は地図の大きさに依存しない。**GLOBAL の粗段が地図面積に比例するのに
対し、TRACK は窓の面積だけで決まる。実測では最大の地図 (52 x 50 m) で
GLOBAL 24.5 ms に対し TRACK 4.5 ms だった。

### 状態機械 (ノード側)

```text
                連続 track_after_accepts 回の採択
       +--------------------------------------+
       |                                      v
    GLOBAL <---- 連続 max_consecutive_rejects 回の棄却 ---- TRACK
```

- 事前姿勢 = 最後に採択した地図姿勢 + それ以降のオドメトリ差分。`/odom` が無い場合は
  最後の採択姿勢そのもの (スキャン間の移動が `track_search_m` に収まる前提)
- TRACK の採否は**事前姿勢からの跳び**で決める (`max_accept_jump_m` /
  `max_accept_yaw_deg`)。探索窓は広いので、窓の中でも遠くへ飛んだ解は単発の誤マッチ
  とみなして捨てる
- 連続棄却が続いたら事前姿勢を捨てて GLOBAL へ戻る (kidnap への対応)
- `~/global_localization` を呼ぶと追跡状態を捨てて GLOBAL からやり直す

## 採択

`wfrac_margin` 未満まで top1/top2 が拮抗したときだけ、**WFRAC** (スキャン点のうち
地図の壁に載らない点の割合) が小さい候補へ選び直す。拮抗していないときは触らない。
選別器ではなく同点決勝という位置づけである。

しきい値 1.05 は 9 地図で較正した値で、「ほとんど発動しない」設定にあたる。
サイノグラム法が WFRAC に +4.4 pt 依存しているのに対し、本手法の依存は +1.4 pt しか
ない (top-1 が既に強いため)。

`global_min_margin` は「top1/top2 がこの値未満なら publish しない」ゲートで、既定 1.0
(実質無効)。誤 commit を嫌う用途では上げる。

## 座標と規約

- 画像座標は x 右、y 下。ワールドへの変換は地図原点・解像度・y 反転をまとめて行う
- スキャン格子はセンサを中心画素に置き、ワールドの yaw と同じ向きに回す
  (画像 y が下向きなので、`getRotationMatrix2D` の正の角がそのまま yaw に対応する)
- `OccupancyGrid` は行 0 が最小 y なので、読み込み時に上下反転して map_server 規約
  (行 0 = 最大 y) に揃える

## 不変条件

- `margin_pixels >= ceil(max_range / match_resolution)`。下回るとテンプレートが地図の
  縁で切れ、縁付近の姿勢を構造的に探索できない。ノードは自動で引き上げて警告する
- `margin_pixels >= ceil(sqrt(2) * max_range / match_resolution) + 1` を満たすと
  相関の外挿が 0 になる (性能のための推奨であって正しさの条件ではない)
- `coarse_angle_step` は 360 の約数
- 地図が無い間は推定しない。有効ビームが 8 本未満なら推定しない
- 候補はスコア降順、NMS で分離済み
- `track()` が返す解は必ず探索窓の内側にある。事前姿勢が地図の外なら空を返す

これらは `tests/test_matcher.cpp` が検査する。

## 既知の制約

- **探索の完全性の保証が無い。**粗段の格子 argmax から降りるので、真のピークが粗格子の
  盆地から外れれば取りこぼす。BBS (Hess 2016) は上界付き分枝限定で探索窓内の最大値を
  必ず見つける。理論的な強さでは BBS が上である
- 長い廊下や周期的な壁配置では複数姿勢が同じ観測を与える。1 スキャンで解けない曖昧さは
  オドメトリ・移動・追加センサで解くしかない (廊下地図での成功率 49〜83% がその実測)
- 粗段のコストは**地図の面積 x 角度数**に比例する。サイノグラム法のコストは地図の
  径に比例するので、**地図が十分大きくなると不利になりうる** (52 x 50 m までは逆転しない)
- 地図が大きいと前計算メモリと初期化時間が増える (段ごとに 3 チャネルのスペクトル)
- 有限レンジ、遮蔽、地図と現場の差は理想的な相関関係を崩す
