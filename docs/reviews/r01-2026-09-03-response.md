削除対象の記述を除去し、runtimeの状態遷移・座標変換・時刻整合、map読込、公開API、
評価とsimulationのfail-fast、CI、依存・再現範囲の文書を更新した。

公開責任者は、過去履歴の旧記述を、後日整理して公開予定の姉妹projectへの言及として許容すると

## 対応体制

対応は、runtime、API・文書、評価・simulation・CIの3領域を別担当へ分けた。主担当は共有
worktreeへ入った変更を統合し、担当間で漏れた依存、library export、状態遷移テストとの接続を
補正したうえで、全体を再build・再testした。

## High

### H1 — サービス要求をTRACK遷移まで保持

`~/global_localization`の要求は、TRACK無効時は最初のGLOBAL採択で、TRACK有効時は
`track_after_accepts`回の連続採択によりTRACKへ移った時点で完了するようにした。曖昧なGLOBAL
結果や候補なし、TF不足では要求を消費せず、次のscanで継続する。実ノードが使用する判定関数を
`test_runtime_support`で検査した。

### H2 — scan frameの外部パラメータを適用

scan時刻の`base_frame <- LaserScan.header.frame_id`をTF2から取得し、全beam endpointを
`base_frame`へ変換してから照合する。TFが無い、frame IDが空、またはtimeoutしたscanは警告して
棄却する。並進とyawを同時に与える単体検査を追加した。

### H3 — 履歴維持を公開方針として採択

公開責任者の判断により、旧記述は将来公開予定の姉妹projectに関する開発履歴として残す。
履歴書換えや新repositoryへの移行は公開条件としない。あわせて、履歴を含めたくなった場合の
任意手段として、source repositoryを書き換えずに1 commitの別repositoryを作る
`scripts/create_public_snapshot.sh`も追加した。許可ケースと禁止文字列混入ケースの両方を
一時repositoryで検証済みである。

## Medium

### M1 — map_server YAMLとorigin yaw

行単位parserを`yaml-cpp`へ置換した。引用符付き・相対・絶対image path、`negate`、
`occupied_thresh`、`free_thresh`、`mode`、origin yawを扱い、不正入力はfieldを示してfail-fast
する。`OccupancyGrid`のorigin quaternionもyawとして照合器へ渡す。path、threshold、mode、
negate、yaw、異常値の単体検査を追加した。

### M2 — scan時刻のodometry

時刻付きodom履歴を保持し、scan時刻を挟むsampleから位置と最短角度差を補間する。補間範囲外は
`odom_sync_tolerance_s`以内の最近傍だけを許し、TRACKまたは`map -> odom`に必要な同期odomが
得られなければ更新またはTF送信を抑止する。補間、角度wrap、許容範囲外の単体検査を追加した。

### M3 — parameter validation

matcherとnodeの有限性、正値・非負値、angle step、pool/level上限、frame名、timing、未知の
`tf_mode`を起動時に検査する。不正値の暗黙補正をやめ、理由付き例外で停止する。

### M4 — library install/export

`oriented_field_matcher`と`map_yaml_loader`のSTATIC library、public header、CMake target、
OpenCV・OpenMP・yaml-cpp依存をinstall/exportする。install済みpackageを
`find_package()`し、名前空間付きtargetへlinkするdownstream smoke testをDocker CIへ追加した。

### M5 — 同一instanceの並行探索

同一instanceの`localize()`と`track()`をmutexで直列化し、段階別時間はlock下で値のsnapshotを
返すようにした。両探索を`std::async`で同時に呼ぶ回帰を追加した。`setMap()`は引き続き、他APIを
呼ぶ前に完了させる契約である。

### M6 — 評価artifactの意図しない再利用

比較・再seed評価は既定でbinary、地図、scan、resultを再生成する。既存結果を使う経路は
`REUSE_RESULTS=1`の明示指定に限定し、必要artifactとmanifestが無ければ停止する。新規runの
manifestにはUTC、引数、環境変数、compiler、地図・source・scan・resultのhashを記録する。

### M7 — archival値と再現可能範囲

日英READMEとbenchmarkで、9地図・5400試行を入力とraw resultが揃わないarchival recordと明記
した。公開物だけで再現できる範囲を、固定seedの合成地図4枚、15条件scan、OFL/BBS対応比較、
集計に限定し、実行commandを掲載した。

### M8 — simulation失敗の伝播

container内process cleanupを`trap`へ分離し、drive processの終了statusを保持する。CSV schema、
行数、終了時刻、有限な推定値を検査し、Nav2ではready・goal送信eventも必須にした。retryを
使い切った場合と集計失敗は非0で終了する。mock Dockerのprocess失敗と短いCSVでfail-closedを
確認した。

### M9 — CIと環境固定

GitHub ActionsでROS 2 Humble Docker build/testを実行するworkflowを追加した。coreとsimulationの
base imageを2026-09-03検証済みmulti-architecture digestへ固定し、core CIはOS、ROS、base、主要
deb versionを出力する。既存imageの使用は`REUSE_IMAGE=1`を明示した場合だけに限定した。
