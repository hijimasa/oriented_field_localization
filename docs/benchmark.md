# ベンチマーク — BBS / Radon サイノグラム法との比較

[English](en/benchmark.md) | 日本語

測定日: 2026-09-01

## 何と比べたか

| 手法 | 中身 | 同梱 |
|---|---|---|
| **本手法 (OFL)** | 画像空間で向き付き場 (壁質量 + 観測側法線) を FFT 相関、ピラミッド粗密探索 | ○ |
| **BBS** | Olson (2009) / Hess (2016) 型の相関型分枝限定。尤度場 + 多重解像度で地図全域 x 全 360 度を探索し、**探索窓内の最大スコア姿勢を必ず見つける** | ○ (`eval/bbs_eval.cpp`) |
| Radon サイノグラム法 | 姉妹パッケージ `radon_global_localization` の NCC-HF | × (数値のみ引用) |

BBS は同一のスキャンダンプを読むので**対応比較**になる。Radon 側は別パッケージの
評価器で同じスキャン集合を解いた結果を引用する (再現手順は末尾)。

## 測定条件

- 地図 **9 枚**
  - 合成地図 4 枚 (`eval/make_synthetic_map.py`、seed 7 / 11 / 23 / 42、30 x 30 m、0.02 m/px)。
    第三者データを含まず、seed 固定で誰でも同一のものを再生成できる
  - Intel Research Lab 2 枚 (29.7 x 28.8 m 0.02 m/px、52.6 x 50.2 m 0.05 m/px)。
    **再配布条件が未確認なので同梱しない**。手元にある場合だけ差し替えて追試できる
  - 廊下地図 3 枚 (15 x 16 m、0.05 m/px)。廊下主体で自己相似が強い
- 地図ごとに **40 姿勢 x 15 外乱条件 = 600 試行**、9 地図で **5400 試行**
- 成功判定: 位置誤差 < 1.0 m かつ 角度誤差 < 15 度
- センサ: 360 ビーム、最大レンジ 10 m、`match_resolution` 0.05 m/px
- 至近レンジゲートは**両手法に同じ 0.8 m** を与えた (下記「ゲートの影響」)
- 時間は 1 スキャンあたりの探索時間の中央値。AMD Ryzen 9 5950X、**16 スレッド**
  (物理コア数。論理 32 まで上げると 2 次元 FFT が SMT で取り合いになり 1.4 倍遅くなる)
- 有意差は McNemar (二項正確検定、両側)

## 結果

| 地図 | OFL top-1 | **OFL + WFRAC** | BBS | OFL [s] | BBS [s] |
|---|---:|---:|---:|---:|---:|
| synthetic_s7 | 91.7% | **94.5%** | 71.0% | 0.010 | 0.013 |
| synthetic_s11 | 87.8% | **91.7%** | 67.7% | 0.010 | 0.013 |
| synthetic_s23 | 90.8% | **93.2%** | 79.0% | 0.010 | 0.013 |
| synthetic_s42 | 94.8% | **96.8%** | 78.2% | 0.010 | 0.013 |
| intel_lab | 99.0% | **99.5%** | 76.3% | 0.010 | 0.020 |
| intel_log | 99.2% | **99.2%** | 89.7% | 0.025 | 0.037 |
| corridor15x | 73.8% | **73.5%** | 37.0% | 0.007 | 0.001 |
| corridor17 | 82.3% | **83.3%** | 34.3% | 0.007 | 0.001 |
| corridor_zigzag | 50.5% | **50.7%** | 29.7% | 0.006 | 0.001 |
| **全体 (5400 試行)** | **85.6%** | **86.9%** | **62.5%** | | |

McNemar (BBS 対 OFL+WFRAC): **OFL だけ成功 1453 / BBS だけ成功 136、p = 1.6e-278**。

**BBS は探索の完全性が証明されている** (探索窓内の最大スコア姿勢を必ず見つける) 手法
であり、本手法にはその保証が無い。それでも成績が離れるのは、**探索の網羅性ではなく
スコアの識別力の差**である。BBS の尤度場は「スキャン点が壁の近くにあるか」しか見ないが、
本手法は壁の**向き**まで一致を要求する。

### 条件別 (全地図プール、5400 試行)

| 条件 | OFL top-1 | OFL + WFRAC | BBS |
|---|---:|---:|---:|
| `clean` (外乱なし) | 91.9% | 93.1% | 64.7% |
| `phantom3` / `8` / `15` / `25` (地図に無い障害物 N 個) | 89.2 / 87.5 / 84.4 / 80.0% | 90.3 / 88.3 / 85.8 / 80.6% | 64.2 / 64.2 / 62.8 / 53.3% |
| `sector60` / `120` / `180` (扇形を至近壁で封鎖) | 88.1 / 82.8 / 75.3% | 89.2 / 83.9 / 73.9% | 64.2 / 56.7 / 39.7% |
| `dropout90` / `180` (扇形が無反射) | 83.3 / 75.3% | 85.3 / 75.8% | 66.7 / 65.8% |
| `mapremove3` / `8` (地図の壁を N 箇所除去) | 95.8 / 98.6% | 97.2 / 98.6% | 68.6 / 73.3% |
| `thin50` / `75` / `90` (ビームをランダム間引き) | 88.1 / 87.2 / 75.8% | 89.2 / 90.0 / 82.8% | 64.4 / 65.3 / 64.2% |

差が最も開くのは `mapremove` (地図と現場の差分) と `sector` (人や台車に囲まれた状況)
で、最も詰まるのは `dropout180` と `thin90` である。

### 至近レンジゲートの影響

`min_range` (この値より近い返り値を捨てる) を 0 と 0.8 m で測った (5400 試行):

| | min_range = 0 | min_range = 0.8 m |
|---|---:|---:|
| OFL + WFRAC | 86.5% | **86.9%** |
| BBS | 57.6% | **62.5%** |

**BBS のほうがゲートに敏感** (+4.9 pt 対 +0.4 pt) である。BBS は点が壁の近くにあるか
だけを見るので、封鎖された扇形の至近壁がそのまま加点されてしまう。本手法は向きまで
見るので、その加点が起きにくい。**上の表は両手法に 0.8 m を与えた条件**である
(BBS に有利な側に揃えてある)。

パッケージの既定は `min_range: 0.0` にしてある。0.8 m というゲートはロボットの
寸法しだいの値で、小型機で一律に切ると実情報を捨てるためである。

### TRACK (局所探索) の成績

収束後の局所探索を、同じ 5400 スキャンに対して**真姿勢を乱数で崩した事前姿勢**
(オドメトリ誤差の模擬) を与えて測った。

| 地図 | GLOBAL | TRACK (事前誤差 <= 1 m / 10 度) | TRACK (<= 3 m / 30 度) | GLOBAL [ms] | TRACK [ms] |
|---|---:|---:|---:|---:|---:|
| synthetic_s7 | 94.5% | **100.0%** | **100.0%** | 9.6 | 4.6 |
| synthetic_s11 | 91.7% | **100.0%** | **100.0%** | 9.6 | 4.5 |
| synthetic_s23 | 93.2% | **100.0%** | **100.0%** | 9.6 | 4.4 |
| synthetic_s42 | 96.8% | **100.0%** | **100.0%** | 9.8 | 4.6 |
| intel_lab | 99.5% | **100.0%** | **100.0%** | 9.5 | 3.8 |
| intel_log | 99.2% | **100.0%** | **100.0%** | 24.5 | 4.5 |
| corridor15x | 73.5% | 91.2% | 90.5% | 6.7 | 4.2 |
| corridor17 | 83.3% | 93.7% | 94.7% | 6.9 | 4.3 |
| corridor_zigzag | 50.7% | 82.5% | 84.5% | 5.6 | 2.5 |
| **全体** | **86.9%** | **96.4%** | **96.6%** | | |

- **窓の内側なら事前誤差の大きさによらず引き込む。**1 m と 3 m でほぼ同じ成績で、
  窓の外 (4 m / 40 度) にすると 92% 前後まで落ちる。設計どおりの挙動である
- **廊下地図の改善が最も大きい** (50.7% -> 84.5%)。自己相似で単一スキャンからは
  一意に決まらない環境でも、事前姿勢があれば曖昧さが消えるためである
- **TRACK の時間は地図の大きさに依存しない。**最大の地図で GLOBAL 24.5 ms に対し
  TRACK 4.5 ms (5.4 倍)

**この測定は事前姿勢の誤差を一様乱数で与えた模擬であり、実機のオドメトリ誤差の分布
とは違う。**ドリフトが溜まる状況での追従と kidnap からの復帰は Gazebo で別に測った
([simulation.md](simulation.md))。動的障害物の連続的な影響はどちらでも測っていない。

### Radon サイノグラム法との比較

姉妹パッケージ `radon_global_localization` の評価器で**同じ 5400 スキャン**を解いた値
(WFRAC のしきい値は手法ごとに較正済み、同じ 16 スレッド):

| 構成 | 成功率 | 時間 [s] 合成 / intel_log / 廊下 |
|---|---:|---:|
| Radon 実機既定相当 (levels=2) | 85.2% | 0.070 / 0.104 / 0.051 |
| Radon levels=3 | 84.3% | 0.053 / 0.065 / 0.044 |
| Radon 最良 (levels=3 + 粗段の位置格子 step 2) | 85.7% | 0.060 / 0.084 / 0.045 |
| Radon 最速 (+ サイノグラム行数半減) | 84.2% | 0.025 / 0.035 / 0.020 |
| **本手法 (OFL + WFRAC)** | **86.9%** | **0.010 / 0.025 / 0.007** |

**成功率で +1.2〜2.7 pt、速度で 2.5〜6 倍**である。両者は表現 (壁質量 + 観測側法線) を
共有しており、違うのは照合を**サイノグラム空間で行うか画像空間で行うか**だけである。
経緯と機構の分析は `radon_global_localization/docs/image_space_control.md` にある。要点:

- サイノグラム空間では「位置」が索引ではなく 180 行を横切る正弦波経路なので、
  位置探索を FFT に落とせず粗い格子 (step 4) に頼る必要がある。画像空間の FFT 相関は
  全位置のスコア場をそのまま返す。
- **同じ候補集合の上で比べても画像空間のスコアのほうが良い選別器である**
  (画像空間が出した候補を Radon のスコアで並べ直すと 85.2% → 73.5%)。
  差は候補生成ではなく順位付けにある。

## 限界

- **9 地図・5400 試行はこの設定の中では十分だが一般化ではない。**センサは 360 ビーム・
  10 m の 1 種類、`match_resolution` も 0.05 固定である。廊下地図 3 枚は 15 x 16 m
  しかなく、10 m のスキャンが地図の大半を覆うので「局所パッチ 対 地図全体」という
  前提から外れている。
- **BBS の実装は評価用のベースラインである。**Cartographer 本体の実装ではなく、
  尤度場 (sigma 0.1 m、打ち切り 0.5 m) と多重解像度分枝限定を素直に書いたものである。
  パラメータを詰めれば数値は動く。
- **本手法には探索の完全性の保証が無い。**粗段の格子 argmax から粗密に降りるので、
  真のピークが粗格子の盆地から外れれば取りこぼす。多重ピーク保持 + NMS + ピラミッドは
  緩和策であって保証ではない。理論的な強さでは BBS が上であり、この点は率直に認める。
- 廊下地図の成功率 (49〜82%) が示すとおり、**自己相似な環境では単一スキャンから
  一意に決まらない**。オドメトリや移動で解くべき曖昧さである。
- 時間は 1 台の x86 マシンでの測定であり、組込み (RPi 等) では比が変わりうる。
- **ここでの TRACK は単発の局所探索としての測定である。**状態機械 (GLOBAL <-> TRACK の
  遷移、跳び棄却、kidnap からの復帰) を含む連続走行は Gazebo で別に測った
  ([simulation.md](simulation.md))。**その検証で「跳び判定だけでは誤ロックを検出
  できない」という欠陥が見つかり、WFRAC ゲートを足して直した。**

## 再現

```bash
cd eval
./run_compare.sh out 40          # 合成地図 1 枚で OFL と BBS を比較
```

9 地図の表を再現するには、`eval/make_synthetic_map.py --seed {7,11,23,42}` で 4 枚を
作り、Intel 地図と廊下地図は各自で用意して、地図ごとに

```bash
OFL_MAP_PGM=<map>.pgm OFL_MAP_RES=<res> OFL_NEAR_WALL_M=8 ./out/make_scans 40 > scans.csv
OFL_MAP_RES=<res> OFL_MIN_RANGE=0.8 ./out/ofl_eval scans.csv <map>.pgm > ofl.csv
OFL_MAP_RES=<res> ./out/bbs_eval scans.csv <map>.pgm 1.0 0.05 0.8 > bbs.csv
python3 summarize.py ofl=ofl.csv bbs=bbs.csv
```

を回す。`make_scans` の姿勢・外乱の乱数系列は `radon_global_localization` の
`disturb_eval2 --dump` と同一なので、**同じ地図・同じ試行数なら両パッケージで
バイト同一のスキャンが得られる** (Radon 側の数値と直接並べられる)。
